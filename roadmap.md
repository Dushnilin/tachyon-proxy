# tachyon-proxy — дорожная карта

> Последнее обновление: 30 октября 2026 года
>
> Статус: release-APK собран для всех ABI; остаётся проверка на устройстве.

## Цель проекта

`tachyon-proxy` — самостоятельный Android VPN-клиент с нуля. Интерфейс делаем
на Flutter: современный, спокойный и похожий по общей подаче на текущий
Tachyon-интерфейс, но без копирования Karing и без зависимости от его исходников.

Сетевой движок — `tachyon-core`. Для Android уже найден отдельный JNI-слой
`G:\tc-head\core-ffi`, который подключает ядро внутри процесса
`VpnService`, принимает TUN-дескриптор и умеет защищать исходящие сокеты от
зацикливания через VPN.

## Найдено в исходных проектах

- `G:\tachyon-core` — основное Rust-ядро, совместимое со схемой конфигурации
  sing-box. Рабочая версия workspace: `0.2.6`.
- `G:\tc-head\core-ffi` — Android JNI-обвязка `libtachyon.so`, версия `0.1.3`.
  Экспортирует запуск, остановку, проверку конфигурации и получение состояния.
- Готовые Android-библиотеки ядра уже собраны для `aarch64-linux-android`,
  `armv7-linux-androideabi` и `x86_64-linux-android`.
- `G:\tachyon-lists` — артефакты списков для tachyon-core в формате `.trs`,
  индекс `release/catalog.json`, а также исходные JSON и списки подсетей.
- `G:\tachyon` — источник логики OpenWrt-клиента. Переносим только
  платформонезависимое поведение; shell/ucode/OpenWrt-сервисы в Android не
  переносятся.
- `G:\morphe-patcher` — другой проект, не используется как основа и не меняется.

## Архитектура

```text
Flutter UI
  └─ Dart application layer
       ├─ profiles and config builder
       ├─ lists catalog and local cache
       ├─ DNS benchmark and selection
       └─ MethodChannel
            └─ Kotlin Android layer
                 ├─ VpnService / TUN
                 ├─ foreground notification
                 ├─ protect socket channel
                 └─ JNI TachyonCore
                      └─ libtachyon.so / tachyon-core
```

Правило границ: Flutter управляет состоянием и настройками, Kotlin владеет
системным VPN-жизненным циклом, Rust владеет сетевым трафиком и маршрутизацией.
Не дублируем маршрутизатор в Dart или Kotlin.

## MVP

В первую рабочую версию входят только:

1. собственный Flutter UI;
2. один рабочий тип профиля;
3. Android `VpnService`;
4. запуск `tachyon-core` через JNI;
5. базовая маршрутизация и выбранные `.trs`-списки;
6. автоподбор DNS с ручным fallback;
7. логи и понятные ошибки.

Импорт большого количества форматов, сложные правила приложений и расширенная
аналитика трафика — после стабильного подключения.

## Текущие блокеры

- Реальное подключение нельзя считать проверенным до запуска на Android-
  устройстве или эмуляторе с рабочим VPN API.
- Нужно подтвердить лицензионные условия распространения `.so` и списков вместе
  с APK.
- Туннель работает по IPv4: IPv6-трафик идёт мимо туннеля напрямую.
- ~~Счётчики трафика~~ — реализованы: ядро отдаёт `traffic_totals()` через
  `TachyonCore.stats()`, UI показывает отправлено/получено и число соединений
  с опросом раз в две секунды.

## Решения по релизу

- Application id: `app.tachyon.tachyon_proxy`.
- Минимальная версия: Android 8.0 (API 26) — под неё собрана `libtachyon.so`.
- ABI в релизе: `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- Подпись: release-APK подписывается debug-ключом, отдельный релизный ключ не
  заведён.
- Разделение трафика по приложениям: режимы «все», «только выбранные»,
  «кроме выбранных».

## Ближайшие действия

1. Установить release-APK на устройство и пройти сценарий
   `check → start → status → stop`.
2. Проверить на устройстве счётчики трафика (опрос `stats()` раз в 2 с).
3. Проверить на устройстве маршрутизацию по спискам и смену сети.
4. Снять скриншоты экранов для журнала изменений.
5. Завести релизный ключ подписи, если сборка пойдёт в Google Play.

> Состояние кода: `flutter analyze` чист, 18/18 тестов зелёные,
> release-APK собран для `arm64-v8a`, `armeabi-v7a`, `x86_64` с
> `libtachyon.so` 0.2.6 (включая JNI `stats`).

## Правила разработки

- Не копировать Karing и не добавлять его как зависимость.
- Не менять `G:\tachyon-core`, `G:\tachyon` и `G:\tachyon-lists` без отдельной
  необходимости; адаптацию держать в `tachyon-proxy`.
- Не писать сетевой маршрутизатор в Dart/Kotlin — это зона `tachyon-core`.
- Секреты не попадают в UI-логи, crash reports и обычный debug log.
- После каждого нетривиального слоя добавлять минимальную запускаемую проверку.
